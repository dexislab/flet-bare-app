# GitHub Actions Workflows Description

## Develop Workflow (`develop-build-linux.yml`)

WHAT DOES: Only builds Flet Linux App

- A simplified workflow to verify builds on regular
  pushes or pull requests - subject for tweaks (!).

- Just a full compilation check to:
  1. Catch build-time bugs early.
  2. Keep `main` always releasable.

### Comments / Notes

• Non-Interactive Flutter SDK Install (--yes).
• Flutter SDK Caching (~/flutter).
• Preserving Executable Permissions (tar -czvf).
• Runner Env: ubuntu-24.04 w/ standard system CMake and Clang.

## Unified Workflow (`main-ci-and-release.yml`)

WHAT DOES: CI & Release (Linux + Android)

1. Regular pushes and pull requests run tests and verify builds.

2. Version tags or manual run execute the parallel 
   Linux + Android builds and publish a GitHub Release.

### How Each Trigger Behaves

• On Pushes to `main`:
  Only the fast `test` job runs, keeping regular commits quick,
  safely skipping `pytest` if no test files exist.
  
• On Pull Requests:
  Both `build-linux` and `build-android` compile your app in 
  parallel to verify nothing is broken. They skip packaging 
  and uploading artifacts, and `publish-release` stays skipped.
  
• On Version Tags (`v*`) or Manual Dispatch:
  Runs the full test and build pipeline, automatically packaging
  and publishing a GitHub Release.

• Manual Dispatch options (`publish_release` checkbox):
  Same as for Tags, but with an option to skip creating a Release.
  There will be temporary artifacts instead: useful to check/test
  your app before making it an official public version.
  
## Why Temporary Artifacts Are Useful

• **Test Before Going Public:** You can download the `.tar.gz` or
  `.apk` from the workflow run summary page and install it on your
  own Linux machine or Android phone to verify it works properly
  before attaching a permanent v1.0.0 release tag.
  
• **Keep Your Releases Page Clean:** GitHub Releases create permanent
  Git tags and notify repository watchers. Temporary artifacts let you
  test work-in-progress builds without cluttering your public Releases
  tab with broken or experimental versions.
  
• **Automatic Cleanup:** GitHub automatically deletes workflow artifacts
  after a set retention period (90 days by default), so test builds do
  not pile up forever.
  
• **Share With Testers:** You can share a direct link to the workflow run
  with collaborators who have repository access so they can download and
  test a feature branch without you having to publish a formal release.
